## Project context

- **Project:** Blockery, a shared Minecraft server and client pack managed from one source of truth.
- **Stack:** Git and Packwiz. The selected Minecraft and loader versions belong in `pack.toml`. Bloom hosts the main and creative deployment targets. Modrinth is the primary client distribution path.
- **Architecture:** Packwiz metadata and shared configuration live at the repository root. Target variations live under `deploy/targets/`. Live server directories, world data, and client instances do not live here.

## Critical rules

- Treat this repository as the canonical desired configuration. Do not use files copied from a live server without reviewing them first.
- Never commit or package secrets, private keys, webhook URLs, RCON credentials, player/admin state, worlds, logs, crash reports, or backups.
- Never commit Floodgate's `key.pem`. Possession of it can allow impersonation of Floodgate-authenticated players.
- Preserve the client/server side declared in Packwiz metadata. Geyser and Floodgate are server-only if they are added.
- Run `packwiz refresh` after manually adding, changing, moving, or removing indexed pack files.
- Keep repository-only files excluded in `.packwizignore` so they are not copied into Minecraft instances.
- Keep shared mods and configuration at the repository root. Put only verified target variations under `deploy/targets/<target>/`.
- Never duplicate a complete pack per deployment target. Build the common pack once and apply the selected target overlay afterward.
- Do not invent version, loader, hosting, deployment, or publishing details. Record them only after they are verified or chosen.

## Commands

These commands require Packwiz. Run initialization only when `pack.toml` does not exist:

- **Initialize:** `packwiz init`
- **Refresh index:** `packwiz refresh`
- **List pack files:** `packwiz list`
- **Export client pack:** `packwiz modrinth export`
- **Update managed files:** `packwiz update --all`

There is no automated test, build, deploy, or publish command yet.

## File-specific notes

- `pack.toml`: Packwiz pack identity, versions, and index reference. Prefer Packwiz commands over manual edits.
- `index.toml`: Generated by Packwiz. Refresh it instead of editing hashes by hand.
- `mods/*.pw.toml`: Download metadata and client/server side declarations. Do not commit downloaded mod JARs when metadata can fetch them.
- `config/`: Include only reviewed configuration intended for distribution.
- `deploy/targets/<target>/`: Keep only reviewed settings unique to that Bloom target. Use templates for files that may contain secrets at runtime.
